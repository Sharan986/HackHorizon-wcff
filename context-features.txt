Design and structure a full-stack healthcare platform called "MedChain" that predicts occupational health risks for industrial workers.

Your goal is to define:

1. Features
2. User flows
3. System flow (data movement)
4. Screen-level breakdown
5. Component hierarchy

Keep it realistic for a hackathon MVP. Avoid overengineering.

---

# 1. CORE CONCEPT

MedChain connects:

* Worker job exposure data
* Medical report data

To generate:

* Risk scores (silicosis, hearing loss, chemical toxicity)
* Clear explanations
* Actionable recommendations

---

# 2. USER ROLES

Define 3 roles:

1. Worker (primary user)
2. Doctor (secondary viewer)
3. Employer (aggregated insights)

---

# 3. FEATURE STRUCTURE

## WORKER FEATURES

1. Authentication

* Login / Register
* Role selection

2. Profile Setup

* Job role (dropdown)
* Years of exposure
* Exposure types (dust, noise, chemicals)

3. Report Upload

* Upload PDF/image
* Preview before submit

4. Report Analysis

* Extract key medical values (FEV1, audiometry, toxicity markers)

5. Risk Dashboard

* Show 3 risk scores:

  * Silicosis
  * Hearing loss
  * Chemical toxicity
* Each score: 0–100 + status (Low/Moderate/High)

6. Explainability

* Show WHY the risk is high/low
* Example:

  * Long exposure duration
  * Abnormal lung function

7. Recommendations

* Preventive actions
* Suggested tests

---

## DOCTOR FEATURES

1. Patient Lookup

* Search worker

2. Clinical View

* Highlight abnormal values
* Show risk scores

3. Flags

* Critical indicators (low FEV1, etc.)

4. Suggestions

* Further tests / follow-ups

---

## EMPLOYER FEATURES

1. Dashboard Overview

* Total workers
* Risk distribution

2. Risk Heatmap

* Zone-based or group-based risk visualization

3. Insights

* “High dust exposure detected”
* “Multiple workers at risk”

---

# 4. SYSTEM FLOW (IMPORTANT)

Define step-by-step data flow:

1. Worker inputs:

   * Profile data
   * Uploads report

2. Backend processing:

   * OCR extracts text from report
   * Extraction layer maps key values

3. Risk Engine:

   * Combine:

     * Exposure data
     * Medical values
   * Generate risk scores (0–100)

4. Explainability Layer:

   * Generate reasons for score

5. Output:

   * Send structured JSON to frontend

---

# 5. DATA STRUCTURE (SIMPLIFIED)

Define models:

User:

* id
* role

WorkerProfile:

* userId
* jobRole
* yearsExposure
* exposureTypes

Report:

* workerId
* fileUrl
* extractedData (JSON)

RiskResult:

* workerId
* silicosisScore
* hearingScore
* toxicityScore
* explanation (JSON)

---

# 6. SCREEN FLOW (UI JOURNEY)

Define clear navigation:

1. Login → Role selection

2. Worker Flow:

   * Profile Setup
   * Upload Report
   * Analysis Screen (loading)
   * Risk Dashboard
   * Recommendations

3. Doctor Flow:

   * Search → Patient View

4. Employer Flow:

   * Dashboard → Heatmap → Insights

---

# 7. UI STRUCTURE

Use:

* Card-based layout
* Clear hierarchy
* One primary action per screen

Each screen should include:

* Header
* Main content card
* Secondary info
* CTA button

---

# 8. CONSTRAINTS (VERY IMPORTANT)

* No complex ML training required
* Use rule-based scoring system
* Focus on clarity and usability
* Prioritize demo flow over completeness

---

# 9. OUTPUT FORMAT

Return:

1. Feature list
2. Flow diagrams (text-based)
3. Screen breakdown
4. Component hierarchy
5. API structure (optional but preferred)

Keep everything structured and implementation-ready.
